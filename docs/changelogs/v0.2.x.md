# v0.2.x 更新日志

## [v0.2.8] - 2026-09-07

### Features

- **画像指令支持默认查询发送者**：`/画像` 未指定用户时直接查询发送者自己的画像，仍支持 @ 用户或输入用户 ID。

### Refactor

- **群规改为手动维护**：新增管理员指令 `/群规 具体规则`，支持覆写当前会话群规；空参数时显示用法和现有群规，WebUI 同步更名为「群规」。

### Bugfix

- **修复外号重复归属与错误累计**：同一机器人、同一会话内外号只允许归属一名成员；外号计数需经过当前聊天中的有效称呼确认，不再因单纯文字命中反复累计。

## [v0.2.7] - 2026-09-06

### Bugfix

- **状态报告补充当前思考展示**：
  - `/查看状态`（别名 `/状态`）的文本和图片响应现在都会展示当前会话的思考内容；
  - 状态报告模板和 WebUI 预览数据新增 `memory` 字段，空白内容显示为「暂无思考」，并保留思考文本中的换行。

## [v0.2.6] - 2026-09-06

### Features

- **状态报告与用户画像指令支持 t2i 图片渲染响应**：
  - `/查看状态`（别名 `/状态`）与 `/查看用户画像`（别名 `/用户画像`、`/画像`）支持以 t2i 图片形式渲染响应，图文并茂展示机器人临时心情、状态、动作、能量看板、常驻状态及用户亲密度好感度、性格态度画像等信息；
  - 插件配置中增加「报告渲染配置」，可自由选择「文本响应」或「图片响应」；图片渲染失败时自动优雅降级为文本响应。
- **Web 控制台新增「报告模板」页签与在线 HTML / Jinja2 编辑器**：
  - 支持在 Web 控制台分别对「状态报告」与「用户画像」两套 HTML 模板进行独立自定义编辑和预览。

## [v0.2.5] - 2026-09-05

### Features

- **支持指令消息入库屏蔽配置开关 (`block_command_messages`)**：
  - 允许在插件配置中屏蔽用户指令输入与 Bot 指令响应入库，避免指令噪音污染对话上下文与历史记录；
  - 插件内置的 `/删除消息` 无论配置开关状态均强制屏蔽入库；
- **新增查看状态、常驻状态设置与会话静默指令**：
  - 新增 `/查看状态`（别名 `/状态`）：直接查看当前会话 Bot 的临时心情、状态、动作、能量看板与常驻状态列表；
  - 新增 `/设置常驻状态`（默认仅管理员可用）：支持在会话中动态新增、更新或删除常驻状态项（如服装、场景、道具等）；
  - 新增 `/静默`（别名 `/休眠`、`/闭嘴`，默认仅管理员可用）：立即将当前会话的 Bot 状态设为「不活跃」并重置接话分析窗口；
  - 移除已废弃的 `/删除数据表` 指令。
- **Web 控制台「决策审计」页签支持单条消息悬浮删除**：
  - 表格增加操作列，鼠标悬浮行时平滑弹出删除按钮（移动端自动常驻适配），支持二次确认后按唯一主键精确删除，并级联清理关联的合并转发与内存缓存；
  - 决策审计与合并转发消息流支持交互点击媒体标签查看与修改转述描述。

### Bugfix

- **修复指令回复引用删除与消息管理机制**：
  - 发送消息时动态拦截并捕获平台端返回的真实数字 `message_id`，杜绝并发竞争；
  - `/删除消息` 仅按真实平台 ID 执行精确删除，避免模糊匹配误删；当遇到无平台记录的指令回复时明确指引用户前往 WebUI 决策审计页面精确删除；

## [v0.2.4] - 2026-09-01

### Bugfix

- **修复官方 QQ 发不出 TTS 语音（日志只留一句没有内容的「处理语音时出错:」）**：
  - 根因是流式合成的语音文件头里写的是占位长度（声称约 2GB）。官方 QQ 需要把语音转成腾讯 silk 才能发送，转码时会照着这个假长度申请内存并直接失败，语音随即被悄悄丢掉、只发出文字；OneBot（aiocqhttp）不解析文件头，所以同一条语音在那边正常，只有官方 QQ 中招。
  - 现在发送前会按文件实际内容重算长度并重写成官方 QQ 编码器最稳的格式（24kHz / 单声道 / 16 位），坏文件头、异常采样率与位宽一并修正。
  - 万一仍然转不了，会把真实原因与调用栈完整写进日志并明确放弃该段语音，不再出现「语音消失且查不出原因」。
- **修复 Webhook 模式的官方 QQ 机器人被当成普通平台**：
  - AstrBot 官方 QQ Webhook 适配器的平台名此前不在识别名单内，导致定时任务与主动消息发言时用不上引用回复、@、撤回、表情包外显等官方 QQ 专属能力，表情包管理页也不会对这些机器人提示「建议开启 GIF」。
  - 现已识别该平台名，且改为容错匹配，后续官方调整命名也不会再漏。

## [v0.2.1] - 2026-08-28

### Refactor

- **统一按需查阅媒体、设置用户头像描述两个工具的机器人归属取值**：这两处仍在手动读取平台信息，平台信息缺失时会取不到机器人名而使工具直接失败；现改用与其他工具一致的容错取值。

### Bugfix

- **修复私聊主动消息在会话标识兜底时丢失用户身份**：当会话标识（`unified_msg_origin`）解析失败而走字段拼装兜底时，私聊没有群号，会话标识会退化成空串，导致该次主动消息的记忆与画像读写全部落到空会话上。现在私聊改用发送者 ID 兜底。

## [v0.2.0] - 2026-08-27

### Bugfix

- **修复定时任务/主动消息触发回复时报 `Mock object has no attribute 'platform_meta'`**：定时提醒走的是伪造事件，一旦对应平台适配器已停用、被改名或尚未加载完成，伪造事件就缺少平台信息，导致工具调用与回复流程直接报错、备用模型也一并失效、该次提醒完全不发言。现在伪造事件始终补齐平台信息，并对全链路的平台信息取值做了容错，取不到时降级处理而不再中断回复。
- **主动消息伪造事件补齐为完整会话上下文**：除平台信息外，消息体、会话标识、发送者、时间戳等信息此前也可能缺失，同一类报错换个字段名就会再次让定时提醒哑火。现在这些字段一律按真实消息构造，未预料到的新字段也会自动降级而不再中断回复；工具调用读取的会话附加信息与回复结果同步给出真实取值，避免主动消息把「工具已直接发过消息」误判成真而漏发回复。
